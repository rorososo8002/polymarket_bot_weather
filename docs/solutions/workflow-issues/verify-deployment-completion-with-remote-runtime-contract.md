# 원격 실행 계약으로 배포 완료를 증명하기

## Context

자동시험 통과, 서버 서비스 `active`, 대시보드 HTTP 200, 파일 복사 성공만으로
“수정과 배포가 끝났다”고 판단했다. 이것들은 프로그램이 설치되고 살아 있다는
증거일 뿐, 사용자가 원하는 매매 흐름이 실제 서버에서 작동했다는 증거는 아니다.

특히 다음 연결을 한 사건으로 확인하지 않았다.

```text
실제 관측 → 봇 수신 → exact NO 후보 판단 → 첫 실행 가능 호가 확인
→ 종이 체결 또는 값이 포함된 명시적 거절
```

그래서 무거래와 무판단 상태가 계속돼도 서버가 켜져 있다는 이유로 완료라고
보고했고, 다음 점검에서 같은 종류의 결함을 다시 발견했다. 문서와 설정의 불일치는
악화 요인이었지만, 근본 원인은 실제 결과를 요구하는 완료 관문이 없었다는 점이다.

## Guidance

배포 확인을 “설치 확인”과 “행동 확인”으로 나눈다. 둘 중 하나라도 빠지면 최종
완료라고 선언하지 않는다.

### 1. 설치 확인

- 로컬과 서버의 배포 대상 파일 지문(파일 내용으로 만든 고유 번호)을 비교한다.
- 새 코드가 올라간 뒤 봇과 대시보드 서비스가 다시 시작됐는지 확인한다.
- 실행 중인 서비스가 읽은 `STRATEGY_MODE`, NO 전용 여부, AWC·KMA·Wunderground
  사용 여부를 확인한다. 설정 파일에 적힌 값만 보는 것으로 끝내지 않는다.
- 원격 전체 시험을 애플리케이션 작업 폴더에서 통과시킨다.

### 2. 행동 확인

같은 도시·현지 날짜·온도 구간·시장 ID로 다음 자료를 연결한다.

1. 관측소가 기온을 기록한 시각
2. 자료원이 그 관측을 공개한 시각(제공될 때)
3. 봇이 관측을 받은 시각
4. 봇이 exact NO 후보 또는 비후보를 판단한 시각
5. 그 판단 뒤 처음으로 실행 가능한 NO 호가를 확인한 시각·가격·수량
6. 종이 체결 시각·평균 진입가·금액, 또는 당시 값이 포함된 구체적인 거절 이유

시간은 UTC 한 기준으로 비교하고 아래 순서를 확인한다.

```text
관측 시각
≤ 봇 수신 시각
≤ 판단 시각
≤ 첫 호가 확인 시각
≤ 체결 또는 거절 시각
```

`paper_decisions.csv`는 “왜 들어갔고 왜 안 들어갔는지 적는 판단 장부”이고,
`paper_trades.csv`는 “실제로 종이 체결된 거래 영수증”이다. 체결이 없으면 판단
장부에서 어느 단계가 왜 막혔는지 확인한다. `기회 없음`, `호가 없음`처럼 넓은
표현만 남기지 말고 가격 상한, 실행 가능 금액, 수수료 반영 수익, 자료 지연,
노출 한도 등 실제 값과 사유를 함께 남긴다.

실제 관측 사건이 아직 발생하지 않았다면 상태를 다음처럼 보고한다.

```text
코드와 설정 배포 확인 완료, 실제 매매 흐름 검증 대기
```

자연 발생 사건을 기다리지 않고도 서버의 임시 장부와 고정 시험자료로
관측→후보→호가→체결/거절 연결을 한 번 재생할 수 있다. 이 재생은 서버에 배포된
코드 경로가 연결됐다는 증거다. 다만 실제 자료원의 공개 지연과 실제 시장 호가는
별도로 관찰해야 하므로, 재생 결과를 자연 발생 사건으로 표현하지 않는다.

## Why This Matters

첫 호가 확인 시각이 없으면 “처음 봤을 때 이미 99센트였는가”와 “봇이 늦어서
99센트가 된 뒤 봤는가”를 구분할 수 없다. 전체 시간선이 있어야 다음 원인을 서로
나눌 수 있다.

- 관측 자료 자체가 늦게 공개됐다.
- 봇이 자료를 늦게 받았다.
- 자료는 받았지만 판단 대기에서 늦어졌다.
- 판단은 빨랐지만 호가 확인이 늦었다.
- 호가는 제때 확인했지만 가격·수량·위험 조건 때문에 거절했다.

이 구분이 없으면 코드 검토를 반복하면서도 실제 무매매 원인과 수정한 부분의
연결을 증명하지 못한다. 반대로 한 사건의 전체 연결이 남으면 다음 점검에서는
추측하지 않고 막힌 한 단계를 바로 고칠 수 있다.

## When to Apply

- 기상 관측 수집 속도나 자료원을 변경할 때
- exact NO 후보 판단 규칙을 변경할 때
- 긴급 처리 순서나 동시 처리 방식을 변경할 때
- Polymarket 호가 수집과 실행 가격 계산을 변경할 때
- 종이 체결, 자금 한도 또는 거절 규칙을 변경할 때
- 배포 뒤 후보·판단·매매가 없거나 이전 문제가 반복될 때

## Examples

잘못된 완료 보고:

```text
시험 통과
봇 서비스 active
대시보드 HTTP 200
파일 복사 완료
따라서 배포 완료
```

올바른 완료 보고:

```text
설치 증거
- 서버와 배포 대상 파일 지문 일치
- 실행 전략: upstream_lock_paper
- 실행 자료원: AWC current cache, KMA public 활성

행동 증거
- 도시·시장: <도시 / 날짜 / exact NO 구간 / market_id>
- 관측 시각: <시각>
- 봇 수신 시각: <시각>
- 판단 시각: <시각>
- 첫 호가 확인: <시각 / 가격 / 실행 가능 금액>
- 최종 결과: <종이 체결 또는 구체적인 거절 이유와 값>
- 단계별 지연: <관측→수신 / 수신→판단 / 판단→첫 호가>
```
