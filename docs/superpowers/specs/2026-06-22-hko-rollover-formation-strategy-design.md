# HKO 자정 이월 및 형성시간 전략 설계

## 목표

공식 관측소의 **당일 누적값이라는 사실이 입증된 자료만** 종이매매 신호에
들어가게 한다. 고정 시각 대신 도시·월·최고/최저별 과거 형성시간과 남은
움직임 분포를 사용하고, 실제 CLOB 주문 가능성이 그 전략을 실행할 수 있는지
마지막 진입 직전에 확인한다.

## 설계

HKO에는 작은 영속 상태 파일을 둔다. 이 파일은 전날 마지막 누적 최고·최저,
현재 관측일, 초기화 확인 상태, 현재일까지 확인된 단조 경계를 저장하는
“자정 인수인계 장부”다. 새 날짜 값이 전날 범위 안쪽으로 실제 축소된 증거가
없거나, 재시작 뒤 전날 기준값이 없으면 실패 닫힘으로 신규 진입을 차단한다.
초기화 뒤 같은 날짜 최고가 감소하거나 최저가 증가하면 그 날짜 자료를 즉시
차단한다. 차단된 원자료와 이유는 감사 표시를 위해 보존하되 확률 계산에는
들어가지 않는다.

잔여오차 저장소는 검증된 manifest에서 도시·월·방향별 관찰 시작 시각과 최종
최고·최저 형성시간 사분위수를 읽는다. 관찰 시작 전에는 일반 YES/NO 확률
진입을 만들지 않는다. 시작 후에는 현재 극값에서 최종 극값까지 더 움직였던
과거 비율과 기존 버킷 확률을 함께 계산한다. 정확한 당일값이 이미 버킷을
깨뜨린 강한 NO만 형성시간과 무관하게 허용한다.

CLOB 최종 조회가 제공하는 `accepting_orders`와 주문장 활성 상태는 계속
필수다. CLOB 자체의 마감 시각 증거가 있고 그 시각이 해당 월 최고기온 형성
구간보다 앞서면 최고기온 확률 진입을 차단한다. Gamma `endDate`만으로 이
판단을 만들지 않는다. 마감 시각을 검증할 수 없으면 대시보드에는 미확인으로
표시하고, 기존의 실제 현재 주문 가능 상태는 반드시 통과해야 한다.

대시보드는 관측소 현지 날짜/시각, 관찰 시작 전후, 형성시간 분포, 추가 움직임
확률, HKO 초기화 상태와 차단 이유, CLOB 주문 가능 상태, 최고/최저 전략의
허용·차단 이유를 한 묶음으로 보여준다. 기존 확률 보정 표시 변경은 보존한다.

## 검증 기준

요청된 HKO 이월·단조성·시간대·DST·형성시간·CLOB 조기마감 사례를 먼저
실패시키고 최소 구현으로 통과시킨다. 기존 49개 도시 관측소 회귀, 전체 pytest,
대시보드 시각 확인, Oracle VPS 전체 pytest를 모두 통과한 뒤에만 새 $1,000
종이계좌를 시작한다.

## 범위 밖

지갑, 서명, 개인키, 실제 주문, 상환, 카피트레이딩은 만들지 않는다. HKO 소수점
정산 구간의 별도 역사 감사가 끝나기 전에는 `needs_audit`를 해제하지 않는다.
